## Bastion project rules

1. The software product name is **Bastion**. “Meshtastic” must not be added to Bastion's primary or secondary product name, edition name, application label, package identity, release-artifact branding, or other product identity.
2. The official Meshtastic logo must not be used as Bastion's application icon or primary branding unless a future use is expressly permitted under the then-current policy.
3. References to Meshtastic® are descriptive compatibility/protocol references only and must not imply sponsorship, endorsement, affiliation, certification, or official status.
4. The first prominent descriptive trademark use in user-facing/support documentation should use the ® symbol and the required attribution notice must remain available.
5. Do not combine BackCountrySignal or Bastion with the Meshtastic® mark in a way that implies an organizational relationship.
6. If a compatibility logo is desired, prefer the published M-Powered/M-PWRD community marks and follow their current usage rules rather than modifying or imitating the official Meshtastic logo.
7. Any upstream software, generated source, assets, or libraries incorporated later must undergo a license review before merge and preserve all applicable license/source/notice obligations.
8. Re-check the current published policy before a public production release because Meshtastic LLC may amend its guidelines.

## Repository naming

Technical source identifiers may use the word `meshtastic` where necessary to describe protocol interoperability (for example codec, BLE service, or packet classes). Such identifiers are implementation descriptions, not Bastion product branding.

The repository itself should use Bastion-only naming where practical to avoid product-name ambiguity.

## Questions or permissions

The published policy directs trademark questions and permission requests to the Meshtastic Trademark Supervisor at trademark@meshtastic.org.
